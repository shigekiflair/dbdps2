# 実装メモ（2026-07-27）：新機能4点

このチャットで実装した4つの機能の引き継ぎメモです。マージ前に必ずセットアップ手順を確認してください。

## 実装した機能

1. **お気に入り・マイページ**（`/mypage`）
2. **停電イースターエッグの予告演出＋演出簡略化/ミュートトグル**（`random-select-tool.tsx`）
3. **イベントトリガー型（`trigger_internal`）の専用UI**（セリフガチャ・お告げガチャ等の1ボタン開示型）
4. **予想・ベッティング型（`betting`）**（裁判ガチャ／視聴者オッズ予想戦。配信者がお題を出し、視聴者が投票、配信者が正解を確定するとランキングが更新される）

## セットアップ手順（必須）

### 1. DBマイグレーション

`db/schema.ts`に以下を追加しました。ローカルで生成・適用してください。

```bash
npm run db:generate
npm run db:migrate
```

追加したテーブル/カラム：
- `plan_favorites`（お気に入り）
- `betting_rounds` / `betting_votes`（予想・ベッティング型）
- `users.isAdmin`（配信者本人かどうかのフラグ。下記2で使う）

### 2. 配信者アカウントに `isAdmin` を立てる（予想・ベッティング型に必須）

予想・ベッティング型の「お題を作る／締切る／正解を確定する」操作は、`session.user.isAdmin === true` のユーザーだけが行えます。誰でもログインできてしまうと荒らされる可能性があるための制限です。

マイグレーション後、一度Twitch/Googでログインしてアカウントを作成 → Neonのコンソールか `psql` で以下を実行してご自身のアカウントを管理者にしてください。

```sql
update "user" set "isAdmin" = true where email = 'あなたのメールアドレス';
```

これを忘れると、予想・ベッティング型のページで「お題を作る」フォームが表示されません（＝ホストとして認識されていない状態）。

## 実装メモ・既知の制約

- **予想・ベッティング型はPusher等のリアルタイム基盤を使わず、6秒間隔のポーリングで実装しています。** 視聴者の投票・配信者の締切/結果発表は最大6秒遅れで反映されます。体感速度が問題になるようなら、次のステップとしてPusher導入をご提案します（`package.json`に依存追加が必要）。
- 投票の得票数・割合は、ラウンドが「締切」または「結果発表済み」になるまで視聴者には見えません（先に投票した人の意見に引っ張られないようにするため）。配信者だけは締切後に見えます。
- ランキングは企画(plan)ごとの累積正解数です。ログインしていない視聴者は名前が「匿名視聴者」表示になります（Cookieでは名前を判別できないため）。ログインすれば名前が出ます。
- イベントトリガー型（`trigger_internal`）は、`customPool`の配列を「山札」として扱い、出し切るまで同じ項目が重複しない設計です。OBS常時表示リンクも発行できます（`target_pick`と同じ`/overlay/[code]`の仕組みを流用）。
- 予告演出（チラ見せ）は、停電になる時は必ず、それ以外の時も約8%の確率で「ガセ」として発生します（本物かどうかは演出が終わるまで分からない、という設計）。この確率は`random-select-tool.tsx`の`maybeTease()`内の`0.08`で調整できます。
- 効果音は音声ファイルを追加せず、Web Audio APIでその場合成しています（`playSound()`）。素材が必要な場合は差し替えも可能です。
