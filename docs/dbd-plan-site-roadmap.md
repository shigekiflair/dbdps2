# DBDパークスロットサイト 拡張ロードマップ

## 前提となる考え方

現状のサイトは「運営(自分)が企画を作り、ユーザーがそれで遊ぶ」という一方向の構造になっている。
これを「ユーザー自身が企画を作り、他ユーザーが遊び、人気企画がランキングで可視化され、
それがさらなる投稿意欲を生む」という循環構造に変えることがゴール。

循環を作るには **投稿 → プレイされる → 数字で評価される → 承認欲求が満たされる → また投稿する**
というループが成立する必要がある。そのためフェーズは「評価の仕組み(ランキング)」を先に固め、
その後に「本格投稿機能」を載せる順番にする(評価軸がないまま投稿の自由度だけ上げると、
何が良い企画か誰にも分からず承認欲求が満たされないため)。

---

## フェーズ0: 土台整備(着手前の整理)

**目的**: 後続フェーズが乗る土台を安定させる

- 既存ツール群(random-select / lottery / tier-list / betting / chain / tracking /
  escalation / target-pick / trigger / data-accumulation / roleplay)の
  データモデルを棚卸しし、「1企画 = 1ツール」から「1企画 = 複数ステージ」に
  拡張できる余地があるかスキーマレベルで確認する
- 通報・非表示の仕組み(admin/reports, admin/trash)が既にあるので、
  投稿型企画にもそのまま流用できることを確認しておく

**成果物**: 現行スキーマのドキュメント化、拡張方針メモ

---

## フェーズ1: 新ツールの量産(コンテンツの物量を増やす)

**目的**: 「遊びつくした」感を薄める。まずは運営主導で企画のジャンルと本数を増やす

- 前回洗い出した案(ハンディキャップオークション、血の商人、育成ログ企画、ビンゴボード等)を
  ジャンルタグ付きで一覧化し、実装優先度をつける
  - 優先度が高いもの: 既存ツールの組み合わせ・軽い拡張で作れるもの
    (逆エスカレーション、レアリティ縛り、リベンジリスト等)
  - 優先度が低いもの: 新規のDB設計や新規UIが必要なもの
    (パークショップ、視聴者製パーク投稿等)
- ジャンルタグ(対人系/心理戦系/収集系/視聴者共創系/継続系など)をplansテーブルに追加し、
  カード表示・絞り込みに使えるようにする(既存のplan-filter-barを拡張)

**成果物**: 新規ツール数本 + ジャンルタグ機能

**このフェーズだけでも**: カードの物量とジャンルの幅が増えるので、体感的な「まだこんなにあるのか」感はすぐ出せる

---

## フェーズ2: 人気順・ランキング機能

**目的**: フェーズ1で増えた企画を「発見しやすく」し、同時にユーザー投稿の評価軸を先に用意する

- 指標の設計
  - プレイ数(ツール実行のログを取る仕組みが必要。現状「引く」ボタン押下がDBに記録される
    ツールとされないツールがあるため、まず全ツール共通のイベント記録を統一する)
  - お気に入り数(favorite-buttonは既存なのでそのまま利用可)
  - トレンドスコア(直近7日プレイ数に重みづけしたスコア。Hot Ranking的な減衰関数)
- 表示面
  - 全体ランキングページ
  - ジャンル別ランキング(フェーズ1のタグを使う)
  - カードへのバッジ表示(🔥トレンド中 / 👑ジャンル1位 など)

**成果物**: プレイ数記録の共通化、ランキングページ、カードバッジ

**依存関係**: フェーズ1のジャンルタグがあるとジャンル別ランキングが作れるので、フェーズ1の後が望ましい

---

## フェーズ3: ユーザー投稿型「本格企画」機能

**目的**: アイデア出し自体をユーザーに委譲し、投稿数そのものを増やす

- **複数ステージ企画**: 1企画内で複数ツールを順番に連結できるようにする
  (例: 抽選 → チェックリスト → エスカレーション、の3ステージを1企画として作成)
  - plan-builderのフォーム(basic-info-form, target-pick-form, tier-list-form,
    lottery-perk-form, string-list-form)を「ステージ追加」の形で繰り返し呼べるように再設計
  - 既存のスキーマに「ステージ」の概念を追加する必要あり(フェーズ0の棚卸しがここで効いてくる)
- **審査フロー**: 単一ツールの簡易企画は即時公開、複数ステージの本格企画は
  「審査待ち → 承認後公開」のワンクッションを入れる
  - 既存のadmin/reports, admin/trashの仕組みをベースに、
    「公開前レビュー」用のステータス(pending/approved/rejected)を追加するだけで実装できる見込み

**成果物**: 複数ステージ企画エディタ、投稿審査フロー

**依存関係**: フェーズ2のプレイ数記録があると、公開後すぐに「どれだけ遊ばれたか」を
投稿者にフィードバックできるので、フェーズ2の後が自然

---

## フェーズ4: クリエイター向けランキング・承認欲求の仕組み

**目的**: 投稿者自身が評価される仕組みを作り、継続的な投稿を促す

- クリエイターごとの合計プレイ数・投稿数を集計するプロフィールページ
- 週間/月間「今週の企画職人」ランキング
- 累計プレイ数が一定閾値を超えた企画を「殿堂入り」としてプロフィールに恒久表示
- (任意)フォロー機能: 特定クリエイターの新着企画を追いたいユーザー向け

**成果物**: クリエイタープロフィール、期間別クリエイターランキング、殿堂入りバッジ

**依存関係**: フェーズ2・3の両方(プレイ数記録 + 投稿機能)が前提

---

## 全体まとめ(依存関係の流れ)

```
フェーズ0 (土台整備)
   ↓
フェーズ1 (新ツール量産・ジャンルタグ) ──┐
   ↓                                    │
フェーズ2 (プレイ数記録・ランキング) ←────┘
   ↓
フェーズ3 (複数ステージ・ユーザー投稿・審査フロー)
   ↓
フェーズ4 (クリエイターランキング・殿堂入り)
```

- フェーズ1と2は先に固めておくことで、フェーズ3でユーザーが投稿を始めたときに
  「すぐに評価される場」が既に用意されている状態になる
- フェーズ3が一番大きな設計変更(複数ステージ対応)を伴うので、
  ここだけ着手前にスキーマ設計を個別に詰めるのが望ましい
